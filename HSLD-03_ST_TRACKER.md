| ST15 | Gmail node false-negative + email failure blind spot | Iterating | 3 | 4 | Closed 2026-09-24. Surfaced during ST14's live testing: the shared n8n "Mail - Post Workspace Migration" node throws `Cannot read properties of undefined (reading 'split')` on every single-send email, but the send succeeds first (confirmed via Gmail's own `labelIds: ["SENT"]` in the node's captured output) — a pre-existing false-negative in n8n's bundled Gmail node, not something this session introduced, already silently affecting the existing admin-initiated `sendPasswordResetEmail` flow before ST14 touched anything. Compounded by a second, separate finding: none of the app's five webhook-firing email functions (`sendWelcomeEmail`, `sendPasswordResetEmail`, `sendVideoTutorialEmail`, `requestPasswordReset`, `requestScheduleTokenPasswordReset`) ever checked the webhook response status, so a genuine send failure would be silently logged as `email_sent` regardless — staff had no way to know. App-side, all five functions now check `response.ok`: the three admin-initiated ones throw, surfacing to the admin UI's existing (previously dead) "· Email failed" catch handling; the two self-service ones route the failure into their existing silent-to-requester/`logSystemActivity`-logged catch blocks, preserving the deliberate anti-enumeration design. Verified live: fresh test correctly routed to the True/Success branch after the If node's operator was corrected from "is equal to" to "contains" (initial config bug, caught via review of the execution's actual routed branch before assuming success).
